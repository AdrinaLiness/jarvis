## [2.7.0] — 2026-10-29

### Изменено — Android v1.4 «только телефон»

- **Запуск приложений — всегда на телефоне.** «запусти спотифай» больше не
  отвечает «steam:// работает только на ПК». Причина найдена: во встроенном
  fallback-списке ярлыков (срабатывал, когда WebView не мог прочитать
  `shortcuts.json` из asset'ов) Spotify и другие приложения указывали на
  steam-ярлыки из ПК-версии. Теперь fallback — только телефонные цели
  (`pkg:com.spotify.music` и т.д.), а Java-мост при любой не-телефонной схеме
  (steam:// и пр.) ищет приложение по имени среди установленных на телефоне
  (умный поиск: псевдонимы → точное → вхождение → нечёткое совпадение).
- **ПК-команды удалены из приложения для телефона**: «выключи/перезагрузи
  компьютер», «заблокируй», «скриншот», «открой папку», «сверни всё»,
  «рабочий стол» и т.п. больше не показываются и не выполняются; из настроек
  исчезли вкладки «Папки», «EXE корни», «Опасные» и пункт палитры
  «Открыть файл по пути».
- **YouTube теперь приложением**: ярлык youtube →
  `pkg:com.google.android.youtube` (раньше открывался сайтом).
- **Не тронуто**: проверка обновлений при каждом запуске — как и раньше,
  через GitHub (`VERSION.json` в репозитории).
- Собран и подписан `ANDROID/JARVIS-v1.4.apk` (versionCode 5, minSdk 24,
  targetSdk 34, тот же ключ из `ANDROID/source/build/jarvis.keystore` —
  ставится поверх v1.3 без удаления). `build_apk.sh` обновлён до v1.4.

## [2.6.0] — 2026-10-29

### Добавлено — проверка обновлений при каждом запуске + GUI-лаунчер

- **`JARVIS-Launcher.bat` v2.0 — графический интерфейс** (WPF, вид как у
  игровых лаунчеров): тёмная тема, анимированный реактор в шапке, 4 карточки
  версий с плюсами/минусами (клик — выбор), выбор папки установки, прогресс-бар
  с бегущей полосой на длинных операциях, журнал установки с цветными строками
  и большая кнопка «ЗАПУСТИТЬ ▶» после установки (для ANDROID —
  «ОТКРЫТЬ ПАПКУ»). Вся логика установки v1.0 сохранена: проверка программ
  до скачивания, winget/страница загрузки, контрольные суммы, pip и go build
  в фоне, `ЗАПУСК.bat` + `О-УСТАНОВКЕ.txt`. Консольный режим на месте:
  `JARVIS-Launcher.bat EXE|HTML|GO|ANDROID` (тихо) и `-Cli` (меню); если WPF
  не открылся, лаунчер автоматически падает в консоль.
- **Самообновление лаунчера**: при каждом запуске лаунчер в фоне сверяет свою
  версию с `VERSION.json` репозитория; вышла новая — янтарный баннер «Доступна
  новая версия лаунчера», кнопка «ОБНОВИТЬ» скачивает свежий файл с проверкой
  контрольной суммы, заменяет им сам себя и перезапускается.
- **`VERSION.json`** в корне репозитория — единый источник версий для всех
  приложений (launcher / exe / html / go / android), заметки и ссылка на
  релизы; именно его читают все приложения при проверке обновлений.
- **Проверка обновлений во всех приложениях JARVIS** (при каждом запуске,
  в фоне, старт не блокируется; офлайн — тихо пропускается):
  - **EXE и GO** (`GO/main.go` v1.3): горутина сверяет версию с VERSION.json
    (сравнение «1.10 > 1.9» — числовое), пишет `[!] Доступна новая версия` в
    лог и отдаёт новый эндпоинт `GET /api/version`; оба бинарника
    `EXE/jarvis.exe` и `EXE/jarvis-server.exe` пересобраны из обновлённых
    исходников, веб-интерфейс в них вшит уже с баннером обновлений.
  - **HTML** (`HTML/backend.py` v1.3): фоновый поток + `GET /api/version`
    (current/latest/update_available); в `HTML/jarvis.html` — плавающий
    баннер «Доступна новая версия JARVIS» с кнопкой «Открыть страницу
    загрузки» (закрывается крестиком, ничего не ломает в вёрстке).
  - **ANDROID** (`ANDROID/source/.../MainActivity.java` v1.3): при каждом
    запуске фоновая проверка; есть новая версия — диалог «Доступно обновление
    JARVIS» с кнопкой «Скачать» (открывает страницу релизов) и «Позже».
- **Android v1.3**: собран и подписан `ANDROID/JARVIS-v1.3.apk`
  (versionCode 4, minSdk 24, targetSdk 34).
  ⚠️ **Подписан новым ключом** (ключ от v1.2 не сохранился при переезде
  окружения) — поверх v1.2 не установится: сначала удали старую версию с
  телефона, затем поставь v1.3. Ключ теперь хранится в репозитории
  (`ANDROID/source/build/jarvis.keystore`, пароль в `build_apk.sh`), так что
  все следующие обновления будут ставиться поверх без удаления.
  `ANDROID/source/build_apk.sh` обновлён: versionCode 4, versionName 1.3,
  имя выхода `JARVIS-v1.3.apk` (плюс `--replace-version` для aapt2).
- Инструкция `О-УСТАНОВКЕ.txt` в каждой установленной папке дополнена
  разделом «Обновления».

## [2.5.0] — 2026-10-29

### Добавлено — Лаунчер для ПК

- **`JARVIS-Launcher.bat`** — установщик «в один файл» для тех, кто не хочет
  разбираться, что качать. Один и тот же файл лежит в `EXE/`, `GO/` и `HTML/`
  и приложен к релизу v1.3.0. Скачал → двойной клик → лаунчер:
  - показывает меню из 4 версий (EXE / HTML / GO / ANDROID) — под каждой
    написаны её **плюсы и минусы**;
  - **до установки** проверяет всё необходимое: интернет, свободное место,
    Python 3.10+ (для HTML), Go 1.21+ (для GO), WebView2 (для EXE); если
    программы нет — предложит поставить через winget или откроет страницу
    загрузки, а после установки перепроверит;
  - скачивает файлы выбранной версии с GitHub **с проверкой контрольных
    сумм** (git-blob SHA1 — сверка байт-в-байт с деревом репозитория; если
    API недоступен или упёрся в лимит — проверка по размерам) и создаёт
    отдельную папку: `JARVIS-EXE` / `JARVIS-HTML` / `JARVIS-GO` /
    `JARVIS-ANDROID` (для GO сохраняется подкаталог `web/` — нужен для
    `go:embed`);
  - после скачивания: ставит pip-зависимости (HTML; если не вышло —
    `Server.bat` сам поставит их при первом запуске), собирает бинарники
    (GO: с gcc — оба exe, без gcc — серверный вариант `CGO_ENABLED=0`),
    пишет в папку `ЗАПУСК.bat` и `О-УСТАНОВКЕ.txt`, предлагает запустить
    JARVIS сразу; для APK печатает, как передать файл на телефон.
- Реализация: bat-заголовок (чистый ASCII — cmd на любом Windows его
  переварит) + PowerShell-payload, который извлекается из самого файла
  по маркеру и запускается без прав администратора; весь вывод на русском,
  цветные меню, повтор скачивания 3 раза, интерактивный выбор имени папки
  при конфликте.
- Тихий режим для скриптов: `JARVIS-Launcher.bat EXE|HTML|GO|ANDROID`,
  флаги `-Force` (переустановка поверх) и `-SkipDeps`.
- Проверено на реальных установках всех 4 версий: SHA1 скачанных файлов
  совпал с GitHub (перекрёстный контроль python-скриптом), папки создаются,
  существующая папка — перезапись или переименование через меню.

## [2.3.0] — 2026-10-29

### Исправлено — Android v1.1

- **Запуск приложений на Android 11+**: в `AndroidManifest.xml` отсутствовал
  блок `<queries>` — без него система скрывает установленные приложения,
  `getLaunchIntentForPackage()` возвращал `null`, и вместо запуска открывался
  Play Market. Теперь JARVIS видит все запускаемые приложения.
- **Открытие целей**: `openTarget` в UI ходит через нативный мост (`open_url`),
  минуя ненадёжный `window.open` WebView (важно для схем `pkg:`).
- **Вёрстка на узких экранах**: канвасы реактора/волны и шапка растягивали
  layout до ~844px в портрете — грид-колонки теперь сжимаются (min-width:0),
  длинные строки журнала переносятся.

### Добавлено — Android v1.1

- **Умный запуск приложений по названию**: «запусти ютуб», «запусти фотошоп».
  Цепочка: псевдонимы RU/EN (ютуб, телега, хрум, плей маркет…) → точное
  совпадение по названию установленного приложения → вхождение → нечёткий
  поиск (Левенштейн ≥ 0.6). Ярлыки пользователя в ⚙ Настройки приоритетны.
- **Комфорт в портрете и ландшафте** (новый `source/patch/layer3.js`):
  ландшафт — три колонки как на десктопе, компактная шапка, чипы в одну
  строку со скроллом (на экранах ниже 380px реактор уступает место журналу);
  портрет — крупное поле ввода 16px (без автозума клавиатурой), высокий
  журнал, подзаголовок бренда скрыт.

### Изменено

- Персона ИИ по умолчанию: `[[RUN:название]]` запускает приложения на телефоне
  по названию (ютуб, телеграм, whatsapp, карты…), а не только по ярлыкам.
- `ANDROID/`: опубликован `JARVIS-v1.1.apk` (versionCode 2; подпись та же —

## [2.1.0] — 2026-10-28

### Добавлено — Settings Panel (GUI)

- **Кнопка «⚙ НАСТРОЙКИ»** в шапке UI — открывает полноэкранный модал настроек.
- **6 вкладок**:
  - **Ярлыки** — CRUD для `shortcuts.json` (добавление/редактирование/удаление ярлыков через UI)
  - **Папки** — список разрешённых папок внутри `%USERPROFILE%` (`Downloads`, `Documents`, + кастомные)
  - **EXE корни** — директории для `launch_exe` (по умолчанию Program Files, + кастомные)
  - **Опасные** — включить/выключить подтверждение для shutdown/restart/sleep/PowerShell/registry/file-edit
  - **Голос** — RU/EN режим, скорость (0.5–2.0), высота (0.5–2.0), кнопка «ТЕСТ ГОЛОСА»
  - **Импорт/Экспорт** — скачать `config.json`, загрузить свой, кнопка «СБРОС К ДЕФОЛТУ»

- **`config.json`** (новый файл) — централизованное хранение всех настроек:
  ```json
  {
    "shortcuts": {...},
    "allowedFolders": [...],
    "allowedExeRoots": [...],
    "dangerousCommands": {...},
    "voice": {"mode","rate","pitch"},
    "server": {"host","port"}
  }
  ```

- **Backend endpoints**:
  - `GET  /api/settings` — отдаёт текущий config
  - `POST /api/settings` — валидирует → бэкапит → сохраняет → применяет в рантайме
  - `POST /api/settings/reset` — сброс к дефолту

- **Runtime-применение настроек** — после POST не нужно перезапускать backend:
  - `ALLOWED_USER_FOLDERS`, `ALLOWED_EXE_ROOTS`, `DANGEROUS_CMDS` обновляются сразу

- **Валидация**:
  - Схемы ярлыков: только `http`, `https`, `steam`, `file` (никакого `javascript:`!)
  - Voice rate/pitch: диапазон 0.5–2.0
  - Whitelist опасных команд: только известные имена

- **Бэкапы**:
  - `~/.dsh/config_backups/config.{ts}.json.bak` — хранятся последние 10
  - Перед каждым сохранением создаётся новый бэкап

- **33 новых теста** в `tests/test_settings.py`:
  - Валидация (schemes, ranges, dangerous toggles)
  - Загрузка/создание config.json
  - apply_config (runtime update)
  - Backup rotation (max 10)
  - HTTP endpoints (GET/POST/reset)
  - Shortcuts loading priority (config.json > shortcuts.json)
  - Audit integration

### Изменено
- `ALLOWED_USER_FOLDERS` теперь mutable (можно менять через GUI)
- `ALLOWED_EXE_ROOTS` теперь хранятся как строки (не Path)
- `_load_shortcuts()` теперь приоритетно читает из `config.json`
- При старте backend загружает `config.json` и применяет `apply_config()`

## [2.0.0] — 2026-10-28

### Добавлено
- **Backend на Python (aiohttp)**: HTTP+WebSocket сервер на `127.0.0.1:8000`.
- **Whitelist команд (31 команда)**:
  - A: `open_url`, `open_path`, `launch_app`, `launch_exe`, `steam_game`
  - B: `system_info`, `volume_set`, `volume_get`, `volume_mute`, `brightness_set`, `shutdown`, `restart`, `sleep_pc`, `lock_pc`, `cancel_shutdown`
  - C: `list_dir`, `create_folder`, `delete_file`, `open_explorer`, `screenshot`, `file_size`, `clipboard_set`, `search_files`
  - D: `media_play_pause`, `media_next`, `media_prev`, `minimize_all`, `show_desktop`
  - E (опасные): `run_powershell` (с маркером `#jarvis-approved`), `edit_registry` (только HKCU\Software\Jarvis\*), `edit_file` (только текстовые расширения)
- **Двойное подтверждение** опасных команд через token (TTL 60 сек).
- **Безопасность**:
  - Слушает только `127.0.0.1` (не `0.0.0.0`)
  - Origin whitelist (`localhost:8000`, `127.0.0.1:8000`)
  - Rate-limit: 10 команд/сек с IP
  - Флаг `--i-understand-the-risks` обязателен для запуска
- **Аудит**: `jarvis_audit.log` (JSON lines), эндпоинт `/audit` для UI.
- **Dispatcher**: класс с `execute()`, `confirm()`, `deny()`, `take()`, `allow()`.
- **`process_request()`** — единая точка входа для WS-сообщений.
- **Тесты (69 шт.)**: pytest, покрыты все whitelist-функции, WS-слой, security.
- **README.md** с 10 разделами (установка, команды, опасные, аудит, откат, тесты, безопасность, архитектура, риски).
- **MARVEL-grade голос**:
  - Улучшенный скоринг голосов (приоритет Google UK English Male, Microsoft George, Apple Daniel)
  - 8 пресетов интонации: `default`, `formal`, `alert`, `confirmation`, `danger`, `thinking`, `boot`, `error`
  - Случайные приветствия при старте (6 вариантов RU/EN)
  - Pre-filler фразы («At once, sir», «Right away, sir» и т.д.)

  - Микро-вариации pitch/rate между фразами (естественность)

- **Индикатор WS** в шапке (зелёный/красный/жёлтый)
- **Панель «АУДИТ»** с автообновлением каждые 3 сек
- **Модал подтверждения** опасных команд (красный overlay)
- **Голосовое подтверждение** «да» / «нет» при открытом модале
- **Новые regex**: «сверни всё», «покажи рабочий стол», «громче», «тише»
- **`Server.bat --test`** — прогон pytest без запуска backend

### Изменено
- **Приоритет команд в `handleCommand`**: BACKEND_PATTERNS проверяются ПЕРВЫМИ (до локальных CMDS). Это исправляет баг, когда «выключи компьютер» перехватывалось локальной командой «Выход».
- **Поле аудита**: `command` → `cmd` (соответствует UI). Фикс бага `undefined` в панели аудита.
- **Regex «Выход»**: `/выключ|отключ/i` → `/^(?:выключись|отключись|заверши работу|пока|goodbye|shutdown)$/i` — теперь ловит только точные фразы, не префиксы.

### Безопасность
- **HKCU-only для реестра**: `edit_registry` принимает только `HKCU`/`HKEY_CURRENT_USER`, путь должен начинаться с `Software\Jarvis\`.
- **Текстовые расширения для `edit_file`**: `.txt .md .json .yaml .xml .csv .ini .py .js ...` (не `.exe`, `.bat` и т.д.).
- **Бэкапы**: перед `edit_registry` → `~/.dsh/registry_backup/{ts}.reg`, перед `edit_file` → `~/.dsh/jarvis_backups/{basename}.{ts}.bak`.
- **Marкер `#jarvis-approved`** обязателен для `run_powershell`.

### Тесты
- 69 тестов в `tests/test_backend.py` (Linux-совместимая часть проходит, Windows-only помечены для запуска на Windows).
- Smoke-test `scripts/smoke_test.py` (7 проверок: ping, commands, unknown, system_info, shutdown+confirm, /audit).
